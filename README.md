# HTML Render MCP

面向 Cherry Studio 的本地 MCP Server，用于把完整结构化页面一次性渲染成可直接显示在对话消息里的 HTML 片段。

当前版本暴露四个最终渲染工具：

- `render_final_html`：最终一次性 HTML 渲染。模型应先完成全部搜索、阅读、分析和内容整理，最后调用一次本工具生成完整连续的 HTML 页面片段。
- `render_upgraded_html`：升级版最终一次性 HTML 渲染。它是完全独立的新工具，参考 `升级技术方案.md` 的“规则系统 + 设计令牌 + 内容类型策略 + 布局组件语法”方案，适合生成更结构化的研究、对比、教程、解读等页面。
- `render_adaptive_theme_html`：自适应主题最终一次性 HTML 渲染。它从“按内容类型换皮”升级为主题感知的信息表达系统：会根据 `contentTypes` / `styleProfile` 自动选择更合适的信息结构，例如新闻倒金字塔、决策简报、学术证据、工作坊路径、观点论证或精选清单。优先使用 `expression` / `expressions` 描述语义，原有 `blocks` 仍保持兼容。
- `render_information_structure_html`：信息结构升级版一次性 HTML 渲染。它参考 `信息结构调整.md`，在 `render_adaptive_theme_html` 的自适应表达基础上显式支持新闻、研究、科普、对比、教程、清单、观点七类信息骨架，并自动匹配对应的视觉风格与表达策略。

这个项目不再默认暴露逐段渲染、外部预览、导出文件、校验等工具，避免模型在生成中途分段调用工具，导致 HTML 页面被工具卡片、思考内容或普通文本打断。

## 安装与构建

```bash
npm install
npm run build
```

开发调试：

```bash
npm run dev
```

正式运行：

```bash
npm start
```

## Cherry Studio MCP 配置

先在本目录执行：

```bash
npm install
npm run build
```

然后在 Cherry Studio 的 MCP 配置中添加：

```json
{
  "mcpServers": {
    "html-render-mcp": {
      "command": "node",
      "args": ["E:/Project/AI/HTMLRenderMCP/dist/index.js"],
      "cwd": "E:/Project/AI/HTMLRenderMCP"
    }
  }
}
```

如果你的 Cherry Studio 配置界面是表单形式，可以填写：

- 名称：`html-render-mcp`
- 命令：`node`
- 参数：`E:/Project/AI/HTMLRenderMCP/dist/index.js`
- 工作目录：`E:/Project/AI/HTMLRenderMCP`

## 推荐提示词

默认稳定渲染模式，调用 `render_final_html`：

```text
请先完成全部搜索、阅读、分析和内容整理，不要在搜索过程中调用 html-render-mcp。
等内容完整后，调用 html-render-mcp 的 render_final_html 一次性生成完整 HTML 页面片段。
最终回复输出工具返回的 HTML，不要使用 Markdown 代码块包裹 HTML，不要一段一段渲染。
```

升级技术方案渲染模式，调用 `render_upgraded_html`：

```text
请先完成全部搜索、阅读、分析和内容整理，不要在搜索过程中调用 html-render-mcp。
如果内容适合用“内容类型策略 + 布局组件 + 设计令牌”组织，请最后只调用一次 html-render-mcp 的 render_upgraded_html。
调用时按内容选择 contentTypes，例如 news、research、explain、compare、tutorial、list、opinion，并用 blocks 组织 hero、summary-card、timeline、stat-grid、comparison-table、quote、risk-box、faq、steps、source-list、callout 等区块。
最终回复只输出工具返回的完整连续 HTML 片段，不要使用 Markdown 代码块包裹 HTML，不要一段一段渲染。
```

自适应主题渲染模式，调用 `render_adaptive_theme_html`：

```text
请先完成全部搜索、阅读、分析和内容整理，不要在搜索过程中调用 html-render-mcp。
如果内容需要更强的主题定制化，请最后只调用一次 html-render-mcp 的 render_adaptive_theme_html。
调用时按内容选择 contentTypes，并优先使用 styleProfile: "auto" 让 MCP 自动匹配视觉画像和表达策略：news 倾向倒金字塔，compare 倾向结论先行的决策简报，research 倾向证据结构，tutorial 倾向工作坊步骤。
优先用 expression / expressions 表达核心观点、摘要、证据、决策矩阵、流程或清单；只有需要兼容旧结构或补充具体布局时再使用 blocks。
最终回复只输出工具返回的完整连续 HTML 片段，不要使用 Markdown 代码块包裹 HTML，不要一段一段渲染。
```

信息结构升级版渲染模式，调用 `render_information_structure_html`：

```text
请先完成全部搜索、阅读、分析和内容整理，不要在搜索过程中调用 html-render-mcp。
如果内容需要按“新闻 / 研究 / 科普 / 对比 / 教程 / 清单 / 观点”的信息骨架呈现，请最后只调用一次 html-render-mcp 的 render_information_structure_html。
调用时优先设置 structure，例如 news、research、explain、compare、tutorial、list、opinion；也可以使用 structure: "auto" 并用 contentTypes 辅助判断。
优先用 expression / expressions 表达核心观点、导语、证据、决策矩阵、流程、排名清单或论证结构；blocks 仅作为兼容或补充布局层。
styleProfile 默认使用 auto，让工具按结构自动匹配 old-newspaper、academic-journal、clean-magazine、decision-brief、workshop-guide、curated-list、editorial-column。
最终回复只输出工具返回的完整连续 HTML 片段，不要使用 Markdown 代码块包裹 HTML，不要一段一段渲染。
```

## 支持的结构

模板：

- `landing-page`
- `report`
- `article`
- `dashboard`

主题：

- `modern-blue`
- `minimal-gray`
- `warm-orange`
- `dark-tech`

区块：

- `hero`
- `features`
- `content`
- `steps`
- `faq`

升级版内容类型（`render_upgraded_html`）：

- `news`
- `research`
- `explain`
- `compare`
- `tutorial`
- `list`
- `opinion`

升级版布局区块（`render_upgraded_html`）：

- `hero`
- `summary-card`
- `timeline`
- `stat-grid`
- `comparison-table`
- `quote`
- `risk-box`
- `faq`
- `steps`
- `source-list`
- `callout`

升级版设计令牌（`render_upgraded_html`）：

- `primaryColor`：主色，安全十六进制颜色，例如 `#2563eb`
- `accentColor`：强调色，安全十六进制颜色，例如 `#f59e0b`
- `fontScale`：`compact`、`normal`、`large`
- `cardRadius`：`none`、`small`、`medium`、`large`、`pill`
- `spacingScale`：`compact`、`normal`、`relaxed`
- `density`：`compact`、`normal`、`comfortable`
- `borderStyle`：`none`、`solid`、`soft`、`accent`
- `shadowLevel`：`none`、`soft`、`medium`、`strong`

自适应主题画像（`render_adaptive_theme_html`）：

- `auto`：根据 `contentTypes` 自动匹配画像，推荐默认使用。
- `old-newspaper`：旧报纸风格，米黄旧纸背景、深墨色文字、低圆角或无圆角、宋体/仿宋一类衬线字体；默认匹配 `news`。
- `academic-journal`：学术期刊风格，白底/浅蓝灰、严谨卡片、低阴影、衬线标题；默认匹配 `research`。
- `clean-magazine`：清爽杂志风格，大留白、柔和色块、适合科普解释；默认匹配 `explain`。
- `decision-brief`：决策简报风格，边界清晰、信息密度中高、适合对比表格；默认匹配 `compare`。
- `workshop-guide`：教程工作坊风格，步骤感强、暖色引导、适合操作说明；默认匹配 `tutorial`。
- `curated-list`：精选清单风格，卡片节奏紧凑、标签和编号突出；默认匹配 `list`。
- `editorial-column`：评论专栏风格，衬线字体、报刊专栏感、适合观点文章；默认匹配 `opinion`。

`auto` 多内容类型优先级：`news` > `opinion` > `tutorial` > `compare` > `research` > `explain` > `list`。如需覆盖自动结果，可显式传入 `styleProfile`。

自适应表达策略（`render_adaptive_theme_html.expression.strategy`）：

- `auto`：推荐默认值，由内容类型、主题画像和 `emphasis` 自动决定。
- `top-down`：总分结构，适合解释、综述、方案说明。
- `inverted-pyramid`：倒金字塔，适合新闻和事件追踪。
- `decision`：结论/建议优先，适合对比选型、决策建议、执行简报。
- `academic`：论点、证据、限制和来源优先，适合研究和调研。
- `workshop`：目标、前置条件、步骤、检查点优先，适合教程。
- `argument`：主张、理由、反方观点、结论优先，适合观点文章。
- `catalog`：筛选标准、排名、标签和适用场景优先，适合清单推荐。

自适应语义表达（`render_adaptive_theme_html.expressions`）：

- `lead`：导语/核心观点，可附关键事实条。
- `key-takeaways`：要点速览。
- `executive-summary`：结论先行的执行摘要/决策简报。
- `evidence-map`：论点、证据、置信度和限制。
- `decision-matrix`：标准、选项、评分和推荐。
- `argument-map`：主张、理由、反方观点和结论。
- `process-guide`：目标、前置条件、步骤、检查点和验收。
- `ranked-list`：排名、标签、适配场景和说明。
- `section-outline`：层级化大纲。

`render_adaptive_theme_html` 至少需要提供一种内容来源：`expressions`、`blocks`，或者 `expression.coreViewpoint` / `expression.keyTakeaways`。其中 `expression` 可自动生成基础导语和要点；`blocks` 是兼容层，不再是唯一推荐结构。

信息结构类型（`render_information_structure_html.structure`）：

- `auto`：默认值，优先根据 `contentTypes` 推断结构；无法判断时回到 `explain`。
- `news`：新闻 / 事件 / 每日要闻，采用倒金字塔，适配 `old-newspaper` 旧报纸风格与 `inverted-pyramid` 策略。
- `research`：研究 / 分析 / 报告，采用执行摘要 + IMRaD，适配 `academic-journal` 学术期刊风格与 `academic` 策略。
- `explain`：科普 / 解释 / 背景说明，采用钩子、类比、原理、意义，适配 `clean-magazine` 清爽杂志风格与 `top-down` 策略。
- `compare`：对比 / 选型 / 决策，采用标准矩阵 + 逐项深评，适配 `decision-brief` 决策简报风格与 `decision` 策略。
- `tutorial`：教程 / 操作指南，采用成果前置、步骤化、验证和故障排除，适配 `workshop-guide` 教程工作坊风格与 `workshop` 策略。
- `list`：清单 / 榜单 / 推荐，采用评选标准、榜单速览、逐项详解和场景推荐，适配 `curated-list` 精选清单风格与 `catalog` 策略。
- `opinion`：评论 / 观点 / 社论，采用立论、论据、反驳、升华，适配 `editorial-column` 评论专栏风格与 `argument` 策略。

`render_information_structure_html` 与 `render_adaptive_theme_html` 复用语义表达结构和设计令牌，但新增 `structure` 作为显式信息骨架入口；当 `expression.strategy` 省略或为 `auto` 时，结构会自动提供策略。它至少需要提供一种内容来源：`expressions`、`blocks`，或者 `expression.coreViewpoint` / `expression.keyTakeaways`。

## 输出约束

- 输出是片段级 HTML，不包含 `<!doctype>`、`<html>`、`<head>` 或 `<body>`，适合 Cherry Studio 消息区直接渲染。
- 样式全部使用行内样式，避免聊天消息环境屏蔽 `<style>`。
- 所有用户文本默认都会 HTML 转义；正文、说明、FAQ 答案等长文本只会放行少量安全内联标签：`<br>`、`<strong>`/`<b>`、`<em>`/`<i>`、`<u>`、`<s>`、`<code>`、`<mark>`、`<small>`、`<sub>`、`<sup>`。带属性的标签和其他标签仍会被转义。
- `render_final_html`、`render_upgraded_html`、`render_adaptive_theme_html` 与 `render_information_structure_html` 都只负责最终 HTML 渲染，不负责搜索、写文件或启动外部预览。
- `render_upgraded_html` 与 `render_adaptive_theme_html` 都是独立工具，不会改变 `render_final_html` 的输入结构和渲染行为。
- `render_information_structure_html` 是独立工具，不会改变其他三个工具的输入结构和渲染行为；它复用自适应表达组件，但通过 `structure` 显式选择信息骨架。
